# NAS 上运行

本项目支持能运行 Linux Python 容器的 Docker 环境。已有基础版本在 x86-64 NAS 验证；其他机型、ARM64及不同厂商界面需要自行实测。不要因为型号有 Docker 就认为全部步骤都已验证。

## 推荐路线

1. 在 NAS 官方应用中心安装 Docker。
2. 将公开发布包解压到你自己的 Docker 项目文件夹。
3. 按首页准备 `data` 和 `.env`；文件夹的用户／组编号需与 Compose 里的编号匹配。
4. 在具备该 Docker 项目管理权限的**交互终端**执行首页的 `setup-user`，由本人隐藏输入登录信息并选择目标。
5. 回到 NAS Docker 项目界面启动 `compose.yaml`，或者在终端运行 `docker compose up -d`。

首次交互设置确实需要一个能控制 Docker 的终端。NAS 的普通日志窗口不能替代它。如果你的账号没有 Docker 权限，请使用厂商支持的管理员操作方式；不要照搬修改 Docker 用户组、免密码 sudo 或开放公网 SSH 的做法。

绿联、群晖等系统的界面、路径和权限不同，这里不提供可能覆盖你现有服务的统一点击脚本。终端操作不熟悉时，请先在本机 Docker 环境试用，再按厂商的容器管理教程迁移。

## 登录数据放在哪里

运行数据只在本项目的 `./data`，映射到容器 `/data`。登录凭据位于其中的 `private` 子目录，绑定配置和队列也在 `data` 中。

- 不把整个数据目录发给其他人、上传 GitHub 或打进部署包。
- 设备迁移时由本人管理登录数据，不能拿别人的数据库覆盖自己的当前队列。
- 同一账号／数据目录只运行一个消费者。切换设备前正常停止旧实例，确认没有正在上传或结果不确定的任务。
- `docker compose down` 的使用和数据保留请先理解你的 NAS 界面行为；不要勾选删除项目文件或数据的选项。

## 升级

等待任务处理完；正常停止服务；只更新公开程序文件和依赖；重新构建、启动并验证。保留自己的 `data` 和 `.env`。不要在无法判断运行状态时覆盖数据库或清空目录。
